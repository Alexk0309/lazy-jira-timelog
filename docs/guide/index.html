Lazy Jira Timelog

A Chrome and Edge extension that notices the time you spend on anything tied to a Jira issue, then hands you a ready list of worklogs to send to Jira in one click. No timer to start, no server, no chat bot.

Chrome & Edge, Manifest V3 Install from a git clone Stores keys, site names, PR titles only Rounds to 15 min by default Log any day Your own ticket list Optional Cursor AI
New in this versionThe Tickets list now shows each ticket's estimate bar, the same one as on Review and Calendar rows.
Overview

How it works

The browser watches only the focused tab. When that tab is about a Jira issue, a background worker writes a small heartbeat every 30 seconds. At review time heartbeats become sessions, sessions become one draft row per issue, and you confirm them before anything reaches Jira.

Counts

Only the focused tab, and only when it's a Jira issue, a PR or branch whose title or name has the key (e.g. PAY-7), or any page showing a known key.

Stops

After 15 min without input, when the screen locks, or 2 min after you switch to something unrelated.

Never sent

Page addresses and browsing history. Only the issue key, the site name and PR titles are stored, in the browser.

Nothing auto-logs

Every worklog, including anything AI drafts, waits for you to press Log.

Getting around

The tab bar

Every view has the same tab bar at the top: Review, Tickets, Calendar and Settings. Tapping one switches the view in place, in the toolbar popup and in a full page alike. No new browser tabs pile up.

Open as a page

In the popup, the arrow button beside the tabs opens the current view in a full browser tab.

Settings from the popup

Opens in a page, reusing one that's already open. The browser's site-access prompt would otherwise close the popup mid-answer.

Settings in a page

Just another tab. Switch back to Review or Tickets without leaving the page.

Use case 01

Install, connect and update

One-time setup from a git clone. You need Git and Node.js 18 or later. The same build works in Chrome and Edge.

Install

  1. Clone the repository and build the extension: 
    git clone https://github.com/Alexk0309/lazy-jira-timelog.git
cd lazy-jira-timelog/browser-extension
npm install
npm run build
    This creates browser-extension/dist. That folder is the extension.
  2. Open the extensions page and turn on Developer mode.
    • Chrome: chrome://extensions, switch at top right.
    • Edge: edge://extensions, switch in the left sidebar.
  3. Click Load unpacked and pick the browser-extension/dist folder. Settings opens by itself.
  4. Enter your Jira site, e.g. https://your-team.atlassian.net.
  5. Choose how to sign in.
    • Browser (default) reuses the Jira session you're already logged in to.
    • API token is the fallback if your company blocks that. Create one at id.atlassian.com → Security → API tokens.
  6. Click Test connection. You should see "Connected as <you>… N projects found."
  7. Self-hosted GitLab or another tool? Add its domain under Sites and allow it when the browser asks.
  8. Pin the extension from the browser's puzzle-piece menu so the badge and popup are always visible.

Update to a newer version

  1. Pull and rebuild: 
    cd lazy-jira-timelog/browser-extension
git pull
npm install
npm run build
  2. On the extensions page, click the reload icon on the Lazy Jira Timelog card. Settings, your ticket list and tracked time are kept.
Don't remove the extension to update itRemoving it deletes its saved data: settings, ticket list and unlogged time. Reload it instead.
Use case 02

Let it track your day

There's nothing to start or stop. Just work.

  1. Open the Jira issue, PR, branch or doc you're working on and keep it focused.
  2. Name branches and PRs with the issue key (PAY-7-refunds, "PAY-7 Refund flow") so time lands on the right issue automatically.
  3. A PR without a key still counts. It's kept as Unassigned under the PR title, and you pick the issue at review (use case 05).
  4. Step away and tracking pauses on its own: 15 min idle, screen lock, or 2 min on unrelated tabs.
  5. Glance at the toolbar icon. The badge shows how much is still unlogged (e.g. 45m, 3h).
Good to knowVery short visits are dropped (sessions under 5 min by default), so flicking past an issue doesn't create noise. Change this under Settings → Ignore sessions under.
Use case 03

Review and log today's time

The core loop, usually once at the end of the day.

  1. Click the toolbar icon. The popup shows today's total "to log" and one row per issue, rounded to 15 min. Use the tab bar to switch to Tickets, Calendar or Settings, and the arrow to open it as a full page.
  2. Tap a row to open it. You can:
    • change the issue in the issue field. Before you type it offers your ticket list, flagged first; typing searches Jira;
    • adjust time with the − / + stepper;
    • edit the comment (PR titles are filled in for you);
    • Split the time in two, then point the new half at another issue;
    • Discard it.
  3. Press Log on a single row, or the big Log 1h 15m button to send every ready row at once.
  4. Logged rows turn green and say Logged. Rows still needing an issue are skipped and counted under the button ("1 entry needs an issue first").
  5. Each row shows the ticket key, its title and, if the ticket has an estimate, a progress bar. See reading the estimate bar.
  6. Missed a day? The orange dot in the week strip marks days with time still to log. See log time on another day.

Reading the estimate bar

Solid blue

Time already logged in Jira against the ticket's original estimate.

Light blue

The time this row is about to add. The label reads e.g. "1h + 1h of 4h".

Red

Logged time has gone over the estimate, e.g. "2h 15m of 2h".

No bar

The ticket has no original estimate in Jira. Logging lowers the remaining estimate, the same way Jira does.

Use case 04

Log time on another day

Forgot yesterday, or worked on something the browser never saw? Review can show and log any past day.

  1. On the Review tab, look at the week strip under the header. Each day shows hours already in Jira; an orange dot means tracked time is still waiting to be logged.
  2. Pick a day by tapping it in the strip, stepping with ‹ ›, or using the calendar button to jump to any date. Future days are greyed out; Today brings you back.
  3. If other days still have time waiting, a line such as "Also to log: Today 45m" links straight to them.
  4. Press Add entry to add time nothing tracked on the day on show. Pick the ticket, type a duration like 1h 30m, add a comment.
  5. Press Log. The worklog is posted on that day (starting 09:00), and the strip updates.
  6. From the Calendar tab, Add log on a selected day opens Review on that day.
Use case 05

Assign time from a PR without a key

Orange Unassigned rows are PR time the extension couldn't tie to an issue.

  1. Find the orange Unassigned row. Its subtitle is the PR title, e.g. "Fix payout CSV export (#51)".
  2. Tap it and type a key or words from the issue summary into the issue field. Pick the match.
  3. Check the comment (it starts as the PR title) and the time.
  4. Press Log. Or let AI suggest the issue (use case 08).
Use case 06

Add work the browser didn't see

Meetings, whiteboarding, local coding. Two ways to capture it.

  1. Look under Touched in Jira today. It lists issues whose status you changed today, and issues assigned to you that were updated today, that have no tracked time.
  2. Tap Add on one (e.g. OPS-12). A row opens with no time yet.
  3. Set the time with +, write a comment, press Log.
  4. For anything not on that list, press Add entry (see another day), describe it to AI (describe your day), or split an existing row and repoint the half.
Why this existsTime outside the browser can't be seen directly. "Touched in Jira today" is the reminder of what you probably worked on.
Use case 07 · updated

Build your ticket list

The tickets you're working on right now, kept in your own order. The issue picker and Fill in with AI use this list first, which helps a lot when Jira is shared by many teams.

  1. Open the Tickets tab.
  2. Add tickets any of three ways:
    • Fetch my assigned tickets adds every open ticket assigned to you in one click;
    • type in Search Jira to add a ticket and pick a result;
    • Paste keys, then paste keys or links (e.g. PAY-12 PAY-14 OPS-3) and press Add. Keys Jira doesn't know are skipped.
  3. Flag the priorities. Tap the flag on one ticket, or tick several checkboxes and press Flag or Unflag in the bar that appears. That bar also has Remove.
  4. Tickets are grouped under their parent.
    • Sub-tasks sit indented under a parent that's on your list.
    • If the parent isn't on your list, it still shows as a shaded heading ("Parent, not on your list"). Its checkbox selects all its sub-tickets at once.
  5. Fold groups away. The count button beside a parent (e.g. 2 ⌄) collapses or expands its sub-tickets. Collapse all and Expand all sit above the list. What you collapsed is remembered.
  6. Set your order. Drag a ticket by its handle, or focus the handle and use ↑ ↓. The heading switches to "Your order"; Sort by created date puts it back to newest-created first.
  7. Tickets with an original estimate in Jira show an estimate bar under them, e.g. "2h 15m of 4h". Tickets without one show no bar.
  8. Keep it tidy. The refresh icon pulls fresh status from Jira, and Remove N done tickets appears when some are finished.
Good to knowThe list is stored in this browser profile, so Chrome and Edge each keep their own.
Use case 08

Fill in with AI

Optional. Cursor writes a one-line comment for each entry and suggests an issue for unassigned time, looking at your ticket list first.

Set up once

  1. In Cursor, open Dashboard → API Keys and create a user API key.
  2. Paste it under AI with Cursor in Settings. Allow api.cursor.com when the browser asks.
  3. Click Test key. Optionally pick a model.

Each day

  1. On the review screen, press ✦ Fill in with AI next to the day heading.
  2. Leave the box empty and press Fill in. You can close the popup while it thinks; the result is waiting when you reopen it.
  3. Check the result. Matched rows show "Matched by AI: <reason>". Cursor prefers tickets on your list, flagged ones first. Every match is checked in code against your list and your open assigned issues.
  4. If Cursor wasn't sure, a row carries a question instead of a guess. See use case 10.
  5. Open any row to tweak it, then press Log as usual.
Not yet tried with a real keySo far this has only been tested against a stand-in for Cursor's API. Each press starts one short Cursor Cloud Agent with no repository, sends that day's issue titles, PR titles and times, your ticket list (up to 60, flagged first) and your open assigned issues, reads its JSON answer and deletes the agent. Runs are billed to your Cursor plan. A 403 means a team admin needs to allow agents without a repository.
Use case 09

Describe your day and let AI add entries

For meetings and other work nothing tracked. Same button, plus one sentence from you.

  1. Press ✦ Fill in with AI. A text box opens above the rows.
  2. Write your day in plain words, with times: "standup 15m, 1h pairing on PAY-12, sprint planning".
  3. Press Fill in. Cursor:
    • sets the time on tracked entries you gave a time for;
    • adds new rows for work nothing tracked, marked "Added from your summary".
  4. Added rows use a ticket on your list, an issue assigned to you, or a key you typed (like PAY-12). If Cursor can't choose, it asks (use case 10); otherwise the row stays Unassigned for you to pick.
  5. Review, assign leftovers, press Log.
PrivacyWhat you type stays on this computer until you press Fill in. Pressing it again replaces entries a previous answer added that you haven't logged yet.
Use case 10

Answer the AI's questions

When two tickets fit about equally, Cursor asks instead of guessing. One tap answers it.

  1. After Fill in, the toast says how many questions need you ("1 question needs your answer").
  2. Find the blue card under the row, e.g. "Which ticket should the 30m interview go to?"
  3. Tap one of the 2 to 4 ticket options. Each shows the ticket summary and, sometimes, why Cursor offered it ("flagged on your list").
  4. The row is filled straight away with no second AI run, and shows "You picked OPS-13". Your answer is remembered if you close the popup.
  5. None fit? Another issue… opens the normal issue picker. Skip leaves the row unassigned.
  6. Press Log as usual.
Use case 11

See, edit, move or delete past worklogs

The calendar shows what's actually in Jira, not what was tracked.

  1. Open the Calendar tab.
  2. The month view shows hours logged per day and the month total. Use ‹ › or Today to move around.
  3. Pick a day. Its worklogs are listed underneath with ticket title, start time, comment and the ticket's estimate bar.
  4. Tap a worklog to change any of:
    • the ticket: type in the issue field and pick another;
    • the date and start time;
    • the duration (type 1h, 45m or use the stepper);
    • the comment.
    Then press Save. If you changed the date, the calendar jumps to the new day.
  5. To remove one, tap Delete, then confirm with Delete again.
  6. Add log above the day's list opens Review on that day so you can add time.
  7. Open in Jira jumps to the issue if you need more.
Moving a worklog is add then deleteJira can't move a worklog between tickets, so Save adds a copy to the new ticket and deletes the original. The worklog gets a new ID in Jira.
Use case 12

Get reminded, once

  1. The toolbar badge always shows unlogged time.
  2. At 17:30 (changeable in Settings → Reminder) you get a single notification, only if something is unlogged.
  3. Click it to open the review page and log.
If everything's loggedNo notification and an empty badge. No nagging.
Use case 13

Tune the settings

Open the Settings tab (from the popup it opens in a page). Changes save as you make them.

SettingDefaultWhat it changes
Site / Sign in withBrowserWhich Jira, and whether to reuse your browser session or an API token.
Reminder17:30When the one daily nudge fires.
Round to15 min5, 15 or 30 min steps for rows and the stepper.
Idle after15 minMinutes without input before time stops counting.
Ignore sessions under5 minDrops brief visits so they don't become rows.
API key / ModelEmptyTurns on Fill in with AI. Model defaults to Cursor's.
